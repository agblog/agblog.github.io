DEADLOCK DEMO EXAMPLE:

In this post we learn dead lock with the example 

Testing pn the following three sessions:  

First Session id =59, 
Second Session id=60,  
Third Session id=61
Following screenshot shows three sessions.



SESSION1: Spid 59

In this session we are going to create two table with some values in it.

Creating table on session 1.
--drop table ##Movies
CREATE TABLE ##Movies(
    MovieId INT IDENTITY,
    MovieName VARCHAR(16),
    Genre VARCHAR(16)
)
GO
--Inserting records
INSERT INTO ##Movies (MovieName, Genre)
VALUES ('Avengers', 'Action'), 
('Iron-Man', 'Adventure')
GO

--Creating another table
CREATE TABLE ##Channels(
    ChannelId INT IDENTITY,
    ChannelName VARCHAR(64),
    Details VARCHAR(16)
)
GO

--Inserting some records
INSERT INTO ##Channels (ChannelName, Details)
VALUES ('UTVAction', 'Multimedia'), 
('SonyMax', 'Movies')
GO

--Selecting records
select * from ##Movies
Select * from ##Channels

SESSION 60:

First we are changing the ISOLATION level of SQL Server from READ COMMITTED to READ UNCOMMITTED.
---1
 BEGIN TRAN;
 SELECT @@TRANCOUNT


SESSION 61:
First we are changing the ISOLATION level of SQL Server from READ COMMITTED to READ UNCOMMITTED.
---1
 BEGIN TRAN;
 SELECT @@TRANCOUNT



SESSION 60:
On the second session we are updating the table named Movies.
---2
UPDATE ##Movies
SET MovieName = 'Hangover'
WHERE MovieId = 1

At this time, The ##Movies table is locked by session 60


SESSION 61:
On third session we are updating another table named Channels.
----3
UPDATE ##Channels
 SET Details = N'Adventures'
 WHERE ChannelId = 1



At this time, The ##Channels table is locked by session 61

SESSION 60:
In second session we are now trying to update the table, that is already being updated by session id 61 and is uncommitted.
---------4
 UPDATE ##Channels
SET Details = N'ForActionMovies'
WHERE ChannelId = 1
GO

Query is taking longer time to than usual, as 1 minute is passed.


This time query execution is in blocked state, taking long wait.

OPEN ANOTHER SESSION:
Checking what is going on, who is blocking:

SP_WHO2 ACTIVE
As seen from following figure, see the session id 60 is blocked by session id 61.


SESSION 61:
Now we are going to update the #Movies table which is locked by the session id 60, which is waiting for session id 61.
-----5                            
UPDATE ##Movies
SET Genre = N'Drama'
WHERE MovieId = 1
GO
This time sql engine performs some smart steps on session id 61 it shows rows affected but on session id 60 see below figure.
SESSION 60:
Is marked as deadlock victim, which is waiting from long time for session id 61 to get complete.
Status:

So, Query Execution is rolled back by database engine and here session id 60 is victim.
After this automatic deadlock handling smart work of database engine when executing.

SP_WHO2 ACTIVE
--Found no blocking sessions




Commit on session 61 and Then drop tables used for testing.

--drop table ##Movies
--drop table ##Channels

sp_readerrorlog:

By default recorded no deadlock information.
The SQL Server records nothing about deadlock if there is not activated any trace flags.

Partitioning can be achieved in two different ways:
  1. With a new table.
  2. With an existing table.
Partitioning Steps:
  • Partition Range Function
  • Partition Schemes
  • Dropping and recreating the Clustered Index on the table to be partitioned

Creating Table and Index: 

CREATE TABLE dbo.PartitionedTable_Existing

(PKID INT IDENTITY(1,1),

 ColA VARCHAR(10),

 ColB VARCHAR(10),

 CreatedDate DATE)

 GO

GO

CREATE NONCLUSTERED INDEX IX_PartitionedTable_COLACOLB ON dbo.PartitionedTable_Existing (ColA,ColB)

  WITH (STATISTICS_NORECOMPUTE = OFF, IGNORE_DUP_KEY = OFF, 

        ALLOW_ROW_LOCKS = ON, ALLOW_PAGE_LOCKS = ON)

Checking if having single partition:



SELECT o.name objectname,i.name indexname, partition_id, partition_number, [rows]

FROM sys.partitions p

INNER JOIN sys.objects o ON o.object_id=p.object_id

INNER JOIN sys.indexes i ON i.object_id=p.object_id and p.index_id=i.index_id

WHERE o.name LIKE '%Partitioned%'

The above table dbo.PartitionedTable_Existing is single partition as partition_number is 1.

--creating partition function and scheme 


CREATE PARTITION FUNCTION PF_PartitionedTable_Existing(DATE)

       AS RANGE RIGHT 

    FOR VALUES ('2015-01-01','2016-01-01')

GO





CREATE PARTITION SCHEME PS_PartitionedTable_Existing

    AS PARTITION PF_PartitionedTable_Existing

TO ([PRIMARY],[Existing2015],[Existing2016]);

GO



--Creating clustered index on Partition Scheme



CREATE CLUSTERED INDEX IX_TABLE1_partitioncol ON dbo.PartitionedTable_Existing (CreatedDate)

  WITH (STATISTICS_NORECOMPUTE = OFF, IGNORE_DUP_KEY = OFF, 

        ALLOW_ROW_LOCKS = ON, ALLOW_PAGE_LOCKS = ON) 

  ON PS_PartitionedTable_Existing(CreatedDate)

GO

Index scans, Index seeks and Table scans:
An index seek uses the tree structure of the index to find a specific data page.
This is a very fast operation, but it can only be used when you want to retrieve single records. The other way to access an index is with an index 

Index scans go through the data pages directly, so they are very suitable for selecting ranges of data or looking for data in columns that arenâ€™t first in the indexing order.
Similarly, a table scan goes through a heap, row by row. If you see a table scan operator in your query plan graph, this means that you should add a clustered index!


Difference between Seek Predicate and Predicate

The seek predicate assists with the join, filtering only to the rows that are also found in the other table (that you've redacted). The predicate (a residual predicate) then eliminates the rows with the specific status of 2. 
The Seek Predicate can be used to find the start of the RangeScan and then when to stop, while the Predicate is the "check" that is applied to every row in the Range.

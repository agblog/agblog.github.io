🛠️ Chapter 2: Hostname Allocation & OS Firewall Setup

Run these commands to establish permanent server identifiers, add local network mappings, and adjust traffic filters.

📋 Sequence 1 to 100: Host Identities & Resolution

001. Run these commands on your respective server nodes to assign unique system network names permanently:

# Execute on Server Node 1
sudo hostnamectl set-hostname rhel-node1

# Execute on Server Node 2
sudo hostnamectl set-hostname rhel-node2

002. Open your static resolution hosts mapping file on both endpoint servers:

sudo vi /etc/hosts

003. Add these IP mapping entries to ensure target hostnames resolve cleanly without reliance on external DNS lookups:

192.168.20.11 rhel-node1
192.168.20.12 rhel-node2

📋 Sequence 101 to 200: Firewalld Rules Routing

💡 Note on Clusterless Topographies: Because we use a clusterless architecture (CLUSTER_TYPE = NONE), data mirroring runs natively inside the database engines. Traditional high-availability cluster daemon ports (such as 2224 or 5405) are omitted by design.

101. Execute these commands on both servers to allow incoming database and replication traffic through the OS firewall perimeter:

# Allow standard database client connection access
sudo firewall-cmd --permanent --add-port=1433/tcp

# Allow Always On endpoint data stream connection mirror traffic
sudo firewall-cmd --permanent --add-port=5022/tcp

# Save and enforce the new active firewall rules configurations immediately
sudo firewall-cmd --reload

# Download pipeline route validation testing tool utilities
sudo dnf install -y telnet nc

102. Run these connection checks to confirm network routes are clear and accessible:

# 1. ICMP basic ping checks (Verify connection from either host)
ping -c 3 192.168.20.11
ping -c 3 192.168.20.12

# 2. Port Validation (Run from Node 2 targeting Node 1 endpoints)
telnet 192.168.20.11 1433
telnet 192.168.20.11 5022

# 3. Port Validation (Run from Node 1 targeting Node 2 endpoints)
telnet 192.168.20.12 1433
telnet 192.168.20.12 5022

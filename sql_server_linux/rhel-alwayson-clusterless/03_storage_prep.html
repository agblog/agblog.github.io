🗄️ Chapter 3: Storage Allocation & Disk Preparation

Separating directory layouts isolates sequential database transaction tracking logs from random data drive reads, optimizing performance.

📋 Sequence 1 to 100: Create Directories & Secure Access

001. Run these commands on both servers to build separate folder trees for your data files, logs, temp tables, and keys:

# Build segregated storage volume paths
sudo mkdir -p /var/opt/mssql/sql-data
sudo mkdir -p /var/opt/mssql/sql-tlog
sudo mkdir -p /var/opt/mssql/sql-tempdb
sudo mkdir -p /var/opt/mssql/backup/agcerts

002. Hand over full directory tree ownership permissions to the native database service worker daemon user account:

sudo chown -R mssql:mssql /var/opt/mssql/sql-data
sudo chown -R mssql:mssql /var/opt/mssql/sql-tlog
sudo chown -R mssql:mssql /var/opt/mssql/sql-tempdb
sudo chown -R mssql:mssql /var/opt/mssql/backup

003. Hardening step: Remove generic public/group read-write access to secure all folders from external system users:

sudo chmod -R 700 /var/opt/mssql/sql-data
sudo chmod -R 700 /var/opt/mssql/sql-tlog
sudo chmod -R 700 /var/opt/mssql/sql-tempdb
sudo chmod -R 700 /var/opt/mssql/backup

📋 Sequence 101 to 200: Apply Kernel SELinux Policies

101. Register the target custom folder extensions into the operating system security core context policy maps:

# Label directories so they are recognized under standard database structures
sudo semanage fcontext -a -t mssql_db_t "/var/opt/mssql/sql-data(/.*)?"
sudo semanage fcontext -a -t mssql_db_t "/var/opt/mssql/sql-tlog(/.*)?"
sudo semanage fcontext -a -t mssql_db_t "/var/opt/mssql/sql-tempdb(/.*)?"
sudo semanage fcontext -a -t mssql_db_t "/var/opt/mssql/backup(/.*)?"

102. Force an immediate recursive context update to apply the security labels across all folder targets:

sudo restorecon -R -v /var/opt/mssql/sql-data
sudo restorecon -R -v /var/opt/mssql/sql-tlog
sudo restorecon -R -v /var/opt/mssql/sql-tempdb
sudo restorecon -R -v /var/opt/mssql/backup

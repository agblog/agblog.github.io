🚀 Chapter 5: Always On Feature Activation, AG Provisioning & DB Sync

This module walks you through activating high availability features, exporting transport certificates, and setting up automatic replication seeding rules.

Step 5.1: Enable the High Availability Engine Module

Run these terminal configurations on both servers to activate the framework extensions:

sudo /opt/mssql/bin/mssql-conf set hadr.hadrenabled 1
sudo systemctl restart mssql-server

Step 5.2 & 5.3: Set Up Security Keys, Certificates, and Backups

Connect to the Primary Server (rhel-node1) and execute this script to generate master keys and the mirror data transport path endpoint:

USE master;
GO
CREATE MASTER KEY ENCRYPTION BY PASSWORD = 'YourStrongKeyPassword99!';
GO

CREATE CERTIFICATE AG_Transport_Cert
WITH SUBJECT = 'Availability Group Replica Transport Authentication',
START_DATE = '2026-01-01', EXPIRY_DATE = '2035-01-01';
GO

CREATE ENDPOINT [Hadr_endpoint]
    STATE = STARTED
    AS TCP (LISTENER_PORT = 5022)
    FOR DATABASE_MIRRORING (
        ROLE = ALL,
        AUTHENTICATION = CERTIFICATE AG_Transport_Cert,
        ENCRYPTION = REQUIRED ALGORITHM AES
    );
GO

-- Back up the security key so it can be trusted by the secondary host node
BACKUP CERTIFICATE AG_Transport_Cert
TO FILE = '/var/opt/mssql/backup/agcerts/AG_Transport_Cert.cer'
WITH PRIVATE KEY (
    FILE = '/var/opt/mssql/backup/agcerts/AG_Transport_Cert.key',
    ENCRYPTION BY PASSWORD = 'YourStrongKeyPassword99!'
);
GO

Step 5.4: Copy Certificates to the Secondary Server

Run these file transfer commands on the Primary Host console to move keys to the secondary node and correct their file ownership mappings:

sudo scp /var/opt/mssql/backup/agcerts/AG_Transport_Cert.* root@192.168.20.12:/var/opt/mssql/backup/agcerts/

# Switch to Server 2 and fix ownership rules
sudo chown -R mssql:mssql /var/opt/mssql/backup/agcerts/
sudo chmod 600 /var/opt/mssql/backup/agcerts/AG_Transport_Cert.*

Step 5.5: Configure the Secondary Replica Node

Connect to your client session on the Secondary Server (rhel-node2) and run this database script to import the transport keys:

USE master;

CREATE MASTER KEY ENCRYPTION BY PASSWORD = 'YourStrongKeyPassword99!';
GO

CREATE CERTIFICATE AG_Transport_Cert
FROM FILE = '/var/opt/mssql/backup/agcerts/AG_Transport_Cert.cer'
WITH PRIVATE KEY (
    FILE = '/var/opt/mssql/backup/agcerts/AG_Transport_Cert.key',
    DECRYPTION BY PASSWORD = 'YourStrongKeyPassword99!'
);
GO

CREATE ENDPOINT [Hadr_endpoint]
    STATE = STARTED
    AS TCP (LISTENER_PORT = 5022)
    FOR DATABASE_MIRRORING (
        ROLE = ALL,
        AUTHENTICATION = CERTIFICATE AG_Transport_Cert,
        ENCRYPTION = REQUIRED ALGORITHM AES
    );
GO

Step 5.6, 5.7 & 5.8: Provision the Availability Group and Sync Databases

Connect to the Primary Server (rhel-node1) to provision the clusterless group:

CREATE AVAILABILITY GROUP [ptag]
WITH (CLUSTER_TYPE = NONE) -- Tells the engine there are no cluster daemon dependencies
FOR REPLICA ON
    N'rhel-node1' WITH (
        ENDPOINT_URL = N'TCP://192.168.20.11:5022',
        AVAILABILITY_MODE = SYNCHRONOUS_COMMIT, -- Guarantees absolute zero data loss
        FAILOVER_MODE = MANUAL,
        SEEDING_MODE = AUTOMATIC,
        SECONDARY_ROLE(ALLOW_CONNECTIONS = ALL)
    ),
    N'rhel-node2' WITH (
        ENDPOINT_URL = N'TCP://192.168.20.12:5022',
        AVAILABILITY_MODE = SYNCHRONOUS_COMMIT,
        FAILOVER_MODE = MANUAL,
        SEEDING_MODE = AUTOMATIC,
        SECONDARY_ROLE(ALLOW_CONNECTIONS = ALL)
    );
GO

Connect to the Secondary Server (rhel-node2) to join the operational session channel:

ALTER AVAILABILITY GROUP [ptag] JOIN WITH (CLUSTER_TYPE = NONE);
GO
-- Give permission to the group to auto-create matching data volumes locally
ALTER AVAILABILITY GROUP [ptag] GRANT CREATE ANY DATABASE;
GO

Finally, return to the Primary Server (rhel-node1) to add your active user databases to the synchronization stream:

CREATE DATABASE EnterpriseAppDB;
GO
ALTER DATABASE EnterpriseAppDB SET RECOVERY FULL; -- Mandatory model for Always On environments
GO

-- Run initial data and transaction log snapshots to initialize the tracking chain
BACKUP DATABASE EnterpriseAppDB TO DISK = '/var/opt/mssql/backup/EnterpriseAppDB.bak' WITH COMPRESSION, STATS = 30;
BACKUP LOG EnterpriseAppDB TO DISK = '/var/opt/mssql/backup/EnterpriseAppDB.trn' WITH COMPRESSION, STATS = 30;
GO

-- Direct the engine to inject the database container into the live synchronization stream
ALTER AVAILABILITY GROUP [ptag] ADD DATABASE [EnterpriseAppDB];
GO

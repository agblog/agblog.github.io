🔍 Chapter 6: Troubleshooting Logs & Health Checking Queries

This chapter provides the tools to monitor your database clusterless sync health and review background service operations.

Step 6.1: Run Command Line Diagnostic Scripts

Run these log commands directly from your server console to trace connectivity anomalies or runtime errors:

# View the last 100 entries inside the native SQL log file
tail -n 100 /var/opt/mssql/log/errorlog

# Search the log file to show only replication and mirroring details
sudo grep -E "Database mirroring|Availability Groups" /var/opt/mssql/log/errorlog

# Pull background system service manager notifications for the database daemon
sudo journalctl -u mssql-server -n 50 --no-pager

Step 6.2: Check Replica Synchronization States

Run this query block inside a database client window to confirm active data protection states across your host replicas:

SELECT
    ar.replica_server_name,
    adc.database_name,
    drs.synchronization_state_desc,
    drs.synchronization_health_desc,
    drs.is_local
FROM sys.dm_hadr_database_replica_states drs
JOIN sys.availability_replicas ar ON drs.replica_id = ar.replica_id
JOIN sys.availability_databases_cluster adc ON drs.group_database_id = adc.group_database_id;
GO

Step 6.3: Monitor Automatic Seeding Progress

Run this database metadata check to verify automatic replication file copy jobs:

SELECT
    start_time,
    completion_time,
    current_state,
    performed_seeding,
    failure_state_desc
FROM sys.dm_hadr_automatic_seeding;
GO

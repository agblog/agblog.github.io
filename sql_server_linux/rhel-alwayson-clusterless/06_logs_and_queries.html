🔍 Chapter 6: Troubleshooting Logs & Health Checking Queries

This chapter outlines how to trace server error event logs and evaluate database sync health states using system queries.

📋 Sequence 1 to 100: Linux Bash Log Diagnostics

001. Run these diagnostic commands from your server console to examine instance error streams and trace runtime logs:

# View the last 100 entries inside the native SQL log file
tail -n 100 /var/opt/mssql/log/errorlog

# Filter the log file to isolate database mirroring or high availability entries
sudo grep -E "Database mirroring|Availability Groups" /var/opt/mssql/log/errorlog

# Review background system manager messages for the database engine process
sudo journalctl -u mssql-server -n 50 --no-pager

📋 Sequence 101 to 200: Core Health Validation Queries

101. Execute this system metadata check inside your query editor window to confirm data synchronization states across replicas:

SELECT ar.replica_server_name, adc.database_name, drs.synchronization_state_desc, drs.synchronization_health_desc, drs.is_local
FROM sys.dm_hadr_database_replica_states drs
JOIN sys.availability_replicas ar ON drs.replica_id = ar.replica_id
JOIN sys.availability_databases_cluster adc ON drs.group_database_id = adc.group_database_id;
GO

📷 [Visual Validation: Database result matrix grid confirming synchronized health descriptions tracks]

102. Run this query to trace active database auto-seeding jobs and verify that file transfers have finished smoothly:

SELECT start_time, completion_time, current_state, performed_seeding, failure_state_desc
FROM sys.dm_hadr_automatic_seeding;
GO

📐 Baseline System Hardware Requirements

Your physical node or virtual machine container must meet or exceed these physical resource limits to successfully launch the core engine process:

Resource Constraint Minimum Threshold Specification Operational Performance Notes
System Memory (RAM) 2 GB Minimum Required to safely execute base internal system threads and process memory managers. Always verify this capacity before adjusting server constraints.
File System Type XFS or EXT4 Format Engine filesystems must use these formats. Dynamic formatting models like BTRFS are entirely unsupported.
Available Disk Space 6 GB Free Space Ensures room for base product libraries and system files under the primary installation paths.
Processor Speed 2 GHz Clock Speed Maintains steady computational speeds and query transaction execution.
Processor Cores 2 Physical Cores Required to manage basic multi-threaded transaction logs and synchronization loops.
CPU Architecture x64-Compatible Only Optimized for 64-bit Intel and AMD processor configurations. Emulation frameworks are not supported.

📐 Virtual Drive & Space Reclaiming Strategies

When provisioning your operating system drives (such as on a new 500 GB layout), adhere to these layout rules:

  • Device Type Mapping: Always designate the disk layout formatting structures to utilize a **Standard Partition** type profile.
  • Reclaim Space Allocation: If you are installing across an old disk, run the **Reclaim Space** command option inside the setup wizard to purge historic volumes and guarantee clean storage tracks.
  • The 185 GB Directory Allocation Matrix: Divide a custom 185 GB chunk from your drive array to isolate the core operating system files. Build separate storage volumes for:
    • /boot (For kernel boot manager files)
    • swap (The system virtual memory paging track)
    • /home (Isolates local user profiles data folders)
    • / (The Root primary system operations volume directory)
  • Expansion Insulation: This layout keeps the remaining 281 GB of your physical drive space unallocated (showing as pink in the setup summary charts), making it perfectly available for side-by-side Windows setups or dedicated secondary database storage groups.

🔑 Red Hat Entitlement Server Registration

❌ Critical Repository Lockout Error: If your Red Hat machine is not authenticated with an active account subscription, attempting to run online package queries will trigger immediate failure alerts such as: "Dependencies Error: As Subscription is necessary to install packages on RHEL."

To authorize package streams, connect to your server console as the **root user** and run these registration lines:

# Update your credentials immediately to attach to the official product channels
subscription-manager register --username your_username --password your_password
📷 Image Indicator: subscription-manager console activation logs check

🌐 Supported Operating System Platforms

The core transaction properties are tested, supported, and validated across these system distributions:

  • Red Hat Enterprise Linux (RHEL): Supported on bare metal or virtual containers on versions 7.3, 7.4, 8.x, 9.x, and 10.x.
  • Ubuntu Server: Fully compatible across LTS releases (including versions 16.04, 18.04, 20.04, 22.04, and 24.04).
  • SUSE Linux Enterprise Server (SLES): Supported on version 12 (SP2 to SP5) and version 15 systems. *(Note: Starting in SQL Server 2025, SLES is no longer supported).*
  • Docker Engine: Supported on version 1.8 or higher platforms on x86-64 processors.
